# 地图、骑行路线与骑手位置

更新日期：2026-11-09。

## 当前实现

地图支持高德 JS API 2.0 和 Leaflet 1.9.4 两种提供商。本机 `configs/map.local.json` 已选择高德，使用真实国内底图、地点搜索与骑行路线。未配置时采用 Leaflet + OpenStreetMap；瓦片地址可配置，保留署名，不批量预取或离线下载。公共瓦片用于轻量演示，生产部署应根据供应商政策配置自己的来源。Leaflet 许可证保存在 `web/assets/vendor/leaflet/LICENSE`。

地图数据来源与渲染提供商相互独立：Discovery 当前只装配 `MAP_SERVICE_PROVIDER=amap` 的高德在线服务；`maps.Local`/`maps.Hybrid` 与 PostGIS 桂林图层代码保留，但尚未接入 `ServiceContext`，配置 `local`/`hybrid` 不会改变实际 provider。差异设计见 `docs/architecture/map-local-services.md`。

用户、骑手和平台页面共用地图组件。标记按实体 ID 缓存在浏览器 Map 中；Leaflet 骑手位置使用移植自 Fleet-Ops 的标记动画，高德使用 SDK MoveAnimation，并遵循同一适配器接口。方向箭头随移动方向更新，文字标签保持直立。支持商家点、任务取送点、浏览器自身位置和授权骑手位置。新任务可点击地图选点，或显式搜索 POI 并选作取件/送达点，地址文字同时回填；单独输入地址文字不会自动调用地理编码。

地图支持分层显隐、查看全部可见点位、选择任务后聚焦取送点，以及主动开启跟随骑手；手动拖动地图或查看全部点位会退出跟随。新任务选点显示经纬度摘要，可以一键清除，发布后立即刷新地图。底图失败时可以点击“重试底图”；新一轮可见瓦片成功加载后清除错误提示。平台附近骑手与单任务跟踪分别维护标记，停止单任务跟踪不会清空平台的附近骑手。

## Fleet-Ops 地图代码复用

实际复制并适配 `fleetbase/fleetops@811aa711a68833dfd8390d8ddac582d4ed75f3c6` 的 `addon/components/leaflet-tracking-marker.js` 与 `addon/services/map-adapter/leaflet.js` 标记方法，位于 `web/assets/vendor/fleetops/`。去掉 Ember 依赖，保留帧插值和标记注册表；地图仍由 CityFlow 原生 JavaScript 与现有 Go API 驱动，没有引入上游订单、企业和调度业务模块。

移植时补充取消旧动画、删除时清理帧、隐藏图层保留目标位置、同 ID 替换不重复挂载、零角度复位和减少动态效果设置。跟随通过标记移动事件驱动，不改变用户原有的拖动和缩放设置。方向是相邻坐标推算方向，不是设备上报航向；动画只改善显示，不代表新增 GPS 采样或道路匹配。

完整来源、修改记录与 AGPL 许可证分别保存在该目录的 `SOURCE.md`、各脚本文件头和 `LICENSE.md`，项目级记录见根目录 `THIRD_PARTY_NOTICES.md`。地图署名提供组件源码入口。用户提供的 Fleetbase 主仓库 ZIP 中子模块为空，本轮使用此前独立取得的上述固定提交源码。

骑手必须主动点击“开始共享位置”，浏览器才每约 10 秒定位并上报；停止共享、离开页面后停止新的上报。浏览器定位要求 HTTPS 或 localhost。任务、浏览器定位、位置接口和 Redis GEO 统一保存 WGS84；高德显示、搜索与骑行接口使用 GCJ02。`map-coordinates.js` 在提供商边界转换，GCJ02 逆变换经过迭代修正，避免反复选点产生偏移；境外坐标保持不变。坐标转换库直接复用 MIT 许可的 `wandergis/coordtransform`。

## 高德配置与路线

启动时自动读取 `configs/map.local.json`（示例为 `configs/map.local.example.json`），或通过 `MAP_CONFIG_FILE` 指定文件。环境变量优先：`MAP_PROVIDER=amap`、`AMAP_JS_KEY`、`AMAP_SECURITY_CODE`、`AMAP_WEB_SERVICE_KEY`。JS Key 必须是「Web端（JS API）」类型且匹配安全码；后端 Key 是「Web服务」类型。空环境变量会覆盖文件值。切换 `MAP_PROVIDER=leaflet` 可使用原有地图。

地图配置使用内部结构分组管理底图、默认城市、中心点、高德密钥、缓存和历史匹配地址；现有平铺 Key 文件继续兼容。完整示例见 `configs/map.local.example.json`，先合并默认值与本地文件，再以环境变量覆盖（包括显式空字符串），启动时校验。变更默认城市时同时设置 `MAP_DEFAULT_CITY`、`MAP_DEFAULT_ADCODE`、`MAP_DEFAULT_LATITUDE`、`MAP_DEFAULT_LONGITUDE`；中心点为 WGS84。热点名单通过本地 `cache.hot_cities` 或逗号分隔的 `MAP_HOT_CITIES` 配置，空值表示不手动指定热点。缓存预算、限流和 TTL 也可在 JSON `cache` 中查看或设置，已有环境变量仍优先。

`/api/v1/map/config` 只返回浏览器需要的信息，不包含 Web 服务 Key。`city_configured`、`search_configured`、`riding_configured` 表示已提供后端服务 Key，并不表示 Key 有效或接口已获授权；具体失败由调用接口返回。为兼容现有客户端暂时保留同义的 `*_enabled` 字段。无效配置会在启动时报错，避免将配置错误静默当作默认值。

前端认证后获取地图配置；Web 服务 Key 只留在 Go 后端。搜索通过 `/v3/place/text`，骑行通过 `/v4/direction/bicycling`，由认证 API 转发固定高德地址，10 秒请求超时。返回异常明确展示错误，不伪造直线路线。搜索和路线只在用户点击时请求，不随 10 秒位置刷新重复计费。

用户可选择新任务取送点或已有带坐标任务规划骑行，显示道路折线、距离、估算时间和逐段指引；改点、切换任务或清除路线会使旧结果与在途请求失效。骑行算法由高德服务提供，Fleet-Ops 的 OSRM driving 接口没有被当作骑行算法复制。规划路线是取件点到送达点的预览，不是骑手实时导航。历史轨迹独立处理定位记录，不以规划路线冒充实际行程。

## 数据流与存储

```text
骑手主动共享位置
    → POST /api/v1/riders/me/location
    → 骑手身份/资料、坐标、定位时间、频率检查
    → Redis 原子脚本更新位置快照、GEO、seen 和待归档轨迹 ZSET
    → 进程内发布 rider.location_changed
    → 按任务鉴权的 WebSocket
    → 更新浏览器骑手标记
```

```text
轨迹异步归档
    → TrackArchiver 每 5 秒读取待归档骑手和游标
    → 按批发布 rider.track.batch.v1 到 cityflow.events
    → tracking.track-archive 消费者写入 cityflow_tracking.rider_track_points
    → MySQL 提交成功后删除 Redis ZSET 中对应 member
```

位置快照的 `rider_id` 使用账号 ID；`version` 是服务端生成的毫秒版本，`observed_at` 是设备定位时间，`updated_at` 是服务端接收时间。Redis 使用统一 `{positions}` hash tag 的键，单脚本完成限频、旧消息过滤、快照存储、GEO 更新和待归档轨迹 ZSET 追加；位置快照 120 秒过期，待归档轨迹不设 TTL，GEO/seen 过期成员由独立 janitor 清理，附近查询会放大候选并过滤无有效快照的成员。单骑手上报间隔至少 10 秒，设备时间需在过去 2 分钟到未来 30 秒内。

未配置 Redis 时使用同接口的内存快照和进程内骑手轨迹，适合单实例开发；没有 MySQL 和 RabbitMQ 时只保留内存/Redis 待归档数据，不启用异步归档。配置 Redis 后如果它不可用，位置接口返回 503，不悄悄改存另一套内存数据；账号状态缓存仍保留原来的故障回源规则。轨迹的最终存储是 MySQL `cityflow_tracking.rider_track_points`，RabbitMQ 消费者提交成功后才删除 Redis 待归档成员；Redis 在归档前丢失的数据无法恢复，任务状态与 `task_events` 时间仍在 Task 自己的 MySQL。

任务新增可空 JSON 字段 `pickup_location`、`destination_location`，通过迁移 `003_task_coordinates.sql` 添加。GORM 和内存仓储均支持这些字段；旧任务不填坐标仍可使用。

## 订阅权限与恢复

- 用户只能查看自己正在履约任务所关联骑手的位置。
- 骑手只能通过自己已接任务查看位置；管理员可以查看活动任务和授权平台位置列表。
- 任务未接取、已完成或已取消后，不提供实时位置和 WebSocket；任务创建者、历史关联骑手和管理员仍可查询历史轨迹。归档/停用的骑手不提供实时位置。
- WebSocket 不接受客户端指定骑手 ID 或任意频道；由服务端从任务查出骑手。
- 浏览器在 WebSocket subprotocol 中传递令牌（`cityflow`、`bearer.<JWT>`），令牌不放在 URL。服务端只协商 `cityflow`，沿用默认同源检查。
- 服务端先订阅事件再读取快照，避免连接建立时的空窗；每次通知重新读取授权快照，另每 5 秒检查令牌有效期、账号状态、任务权限和位置过期情况。
- 浏览器通过 REST 获取快照，并按 `version` 忽略旧消息；断线退避重连时重新获取快照，位置断连/过期时清除骑手标记。
- 已收到新的 WebSocket 事件或连接断开后，忽略此前仍在途的 REST 快照，避免过期标记重新出现。浏览器从前进/后退缓存恢复页面时重新加载地图与订阅。

## 第一阶段的边界

- 事件总线仅在单个 API 进程内广播；Redis 存位置不代表已实现跨实例推送。若扩为多实例，需要 Redis Pub/Sub 或其他事件桥接；当前 5 秒心跳重读共享快照不能替代正式的多实例事件设计。
- 地图任务和商家各取当前前 100 条记录；当前选中的跟踪任务不在第一页时单独读取并保留其取送点，只有确认结束或无权访问才停止跟踪，暂时请求失败保留选择。其他超出第一页的任务仍未实现地图检索/选择器分页。平台位置查询按地图中心 50 公里范围展示最多 100 个近期骑手。没有全城海量点位聚合或容量压测结论。
- 开放任务仍未按距离筛选，骑手页面已改名为“开放任务”。附近骑手搜索只向管理员开放，不向所有用户暴露骑手位置。
- 商家只是地图地点投影，没有景点评价、推荐、商品交易或商家自动关联任务。
- 商家在自己的工作台新增/查看/编辑/归档门店，地图选点与搜索回填仅修改草稿，保存后其他端地图读取最新位置。公开地图只显示营业中的门店；暂停、关闭、归档后隐藏。后台约 30 秒刷新，手动“刷新地图”立即请求商家数据。没有新增平台地图管理表单。
- 已接入高德骑行预览及骑手历史轨迹道路匹配；按用户要求不做逐向导航，仍未实现自动调度。
- 设备位置来自浏览器授权上报，不等同于经过校验的真实行程或防作弊定位。

## 本地联调

默认启动 Compose 后按本地开发文档运行 API；MySQL 映射到 `3307`、Redis 映射到 `6380`、RabbitMQ 映射到 `5673` / `15673`。各服务使用 `.env` 中的 `IDENTITY_DATABASE_DSN`、`TASK_DATABASE_DSN`、`DISCOVERY_DATABASE_DSN`、`PAYMENT_DATABASE_DSN`、`REACTION_DATABASE_DSN`、`TRACKING_DATABASE_DSN` 和共享的 `REDIS_ADDR`、`RABBITMQ_URL`；Tracking 使用独立的 `cityflow_tracking` 库保存轨迹归档，Redis 只保留快照和待归档点。需要改端口时，在启动 Compose 时设置 `MYSQL_PORT` / `REDIS_PORT` / RabbitMQ 端口，并同步修改 `.env`。

以用户账号登录，地图选点并发布任务；另开浏览器会话用骑手账号接单并点击“开始共享位置”。用户刷新地图任务列表，选择该任务，即可看到骑手标记。无定位设备时可以在浏览器开发工具中模拟位置。完成或取消任务后，停止跟踪。

## 骑手历史轨迹（MySQL 归档 + Redis 待归档）

仅记录骑手，不采集用户个人历史轨迹。骑手主动共享并成功上报后，服务端在 Redis 中按 `rider_id` 追加一条采样，不按任务复制；任务归属在查询时由 Task 的 `task_events` 时间窗解析。这样同一骑手同时履约多个任务时，一次上报只存一份轨迹，不同任务查到的时间段不同。`task_id` 只作为实时展示标注，不参与历史归属；早于接单、晚于完成/取消的采样不会进入该任务的历史。

Redis 待归档 ZSET 为 `cityflow:{positions}:track:rider:{riderID}`，`score` 是服务端接收毫秒，`member` 是位置 JSON；Lua 同时把骑手加入 `cityflow:{positions}:track:riders`，并用 `cityflow:{positions}:track:cursors` 保存每个骑手的归档游标。ZSET 不设 TTL，但它是待归档队列，不是最终存储：归档器每 5 秒按游标取一批点（默认 100），发布到 `cityflow.events` 的 `rider.track.batch.v1`，持久队列为 `tracking.track-archive`；消费者成功写入 MySQL 后才 `ZREM` 对应 member，队列为空时清理骑手集合和游标。发布成功先推进游标，发布失败不推进；消费者失败会重试，超过重试次数进入 `tracking.track-archive.dlq`，此时 Redis 点仍在，归档器会在点超过 2 分钟后回退游标重放，同一骑手最多每 5 分钟回退一次，MySQL 唯一键吸收重复。归档器启动时还用一次 `SCAN` 把旧版 `track:rider:*` 键的 riderID 补进 `track:riders`，升级前遗留的轨迹也会被归档并从 Redis 删除。

MySQL 最终表是 `cityflow_tracking.rider_track_points`，字段为 `id`、`rider_id`、`task_id`、`latitude`、`longitude`、`accuracy`、`source`、`observed_at`、`updated_at`、`version`；唯一键 `rider_track_version(rider_id, version)` 保证 MQ 重投幂等，查询索引为 `rider_track_observed(rider_id, observed_at, version)` 和 `rider_track_task(task_id, observed_at)`。轨迹当前永久保留，未设置保留期或清理任务。

历史读取使用 `MergedTrackReader`：同时读 MySQL 归档和 Redis 待归档点，按 ID 去重（MySQL 副本优先），再按 `after` 过滤并分页。Redis pending 查询固定从 `after=0` 开始，不能直接使用归档游标，因为游标可能在 MySQL 提交前已经推进；直接用游标会跳过尚未落库的点。

当前位置快照与待归档轨迹在同一个 Redis Lua 中原子写入，写成功后才发布实时事件。历史读取失败不会影响实时上报；Report 成功只表示快照和待归档点已写入 Redis，不代表 MySQL 已落库。Redis 重启/主从切换可能丢失尚未归档的点；已经由消费者提交到 MySQL 的轨迹不受影响。任务事实和时间仍在 Task 自己的 MySQL。

### 展示处理

历史接口默认每页 100 点，最大 500 点，`after` 是服务端 ID 游标，返回 `next_cursor` 和 `has_more`。前端每次加载 500 点，可继续加载后续记录；相邻页匹配时复用前页最后一条观测，以保持边界衔接。只有用户点击加载才请求匹配，不随 5 秒轮询重复请求。

1. 剔除精度差于 100 米、非递增时间与明显跳点；抑制小于 2 米的静止抖动，数据库原始记录不删除。
2. 观测间隔超过 120 秒或出现严重漂移时断开，不跨断点补线。
3. 调用 OSRM `/match/v1/cycling/` 骑行道路匹配，携带观测时间和精度半径，每批最多 100 点、批次重叠一个点。仅采用置信度至少 0.5 且所有输入点有匹配的结果。匹配仍是估算，不是定位真实性证明。
4. 高德/Leaflet 根据道路几何绘制绿色实线与圆角接头，让轨迹沿道路自然弯曲，不用任意贝塞尔曲线抹平真实拐弯。不足 3 个有效点、服务不可用或低置信度时，用虚线标明原始定位连线，孤立点仅显示小圆点。

`MAP_MATCH_URL` 可配置自己的 OSRM 骑行实例地址，设为 `disabled` 可禁用外部匹配。开发默认使用 `https://routing.openstreetmap.de/routed-bike` 公共演示服务，请求会向该服务发送所选轨迹坐标、时间和精度；它没有生产容量或可用性保证，正式部署宜配置自建/合适的服务。单请求 6 秒，单次展示总计最多 20 秒，超时降级为明确标注的定位连线。

已查看 Fleet-Ops 固定提交的 `addon/components/map/drawer/position-listing.js`（历史位置与回放）和 `addon/services/osrm.js`（规划路线）。相关实现没有可直接移植的骑行道路匹配；本轮历史模块是 CityFlow 的 Go/JS 实现，匹配由 OSRM 开源服务提供，未复制上游业务模型。

### 历史轨迹验证

`node scripts/map-history-smoke.cjs` 通过 `CITYFLOW_TEST_URL` 指向独立的、配置真实 Redis、MySQL 和 RabbitMQ 的演示服务。脚本创建并取消任务，用模拟的骑行位置序列验证真实上报、权限、结束后查询、外部匹配及桌面/手机显示；脚本不直接查询数据库，MySQL 归档与 MQ 消费由 Go 集成测试覆盖。模拟数据不能当作真人骑行证据；任务保留以验证重启后历史仍在（已归档点来自 MySQL，未归档点来自 Redis 待归档）。截图在系统临时目录 `cityflow-history-smoke`。

2026-11-08 实测 9 个模拟观测点匹配成 28 个道路几何点，置信度约 0.958；Go 测试覆盖低置信度降级、断点、漂移、分页、跨用户权限、终态查询、重复版本与轨迹读取。

## 城市视野、热点缓存及调用保护（2026-11-09）

用户、骑手和平台地图新增“定位到我”“查看当前城市全市”“显示行政区边界”。默认浏览桂林；浏览器成功定位后显示附近约数公里，通过高德逆地理编码识别实际城市，再按行政区边界适配全市。定位只在当前页面内存保存，不启动骑手共享，也不记录用户历史轨迹。边界仍为 GCJ02，经转换后供 WGS84 地图适配器使用。

`GET /api/v1/map/city?latitude=…&longitude=…&coordinate_system=GCJ02` 返回所在城市；服务端按约 0.01° 网格中心逆查，不向供应商提交用于识别城市的精确定位。`GET /api/v1/map/district?adcode=450300` 返回边界。这些接口和其他 `/map` 接口均需有效登录；每个账号每进程限制 120 次/分钟，超过返回 429 和 Retry-After。骑手权限仍由任务位置接口单独校验，城市功能不扩大订阅权限。

### 商家范围查询

`GET /api/v1/map/merchants?west=…&south=…&east=…&north=…&zoom=…` 按 WGS84 视野查询，只返回有效账号下未归档、营业中的公开门店投影。新增迁移 `005_merchant_map_index.sql`。前端停止使用前 100 家列表，拖动/缩放结束后防抖 300 毫秒，取消过时请求并检查响应代次；后台约 30 秒重取，点击刷新立即重取。

放大到 zoom≥13 时，以 0.1° 网格缓存公开商家投影 45 秒，最多查询 64 格，每格最多显示 500 家、每次最多 1000 个点；超限显示提示，建议继续放大。按 ID 去重并过滤出当前视野。zoom<13 使用一次有界数据库范围查询（最多 10001 行，显示最多 10000 家对应的聚合），避免全市遍历数百网格；按 0.1° 或 0.4° 聚合，最多返回 1000 个聚合/独立点，点击聚合后展开。低缩放概览只合并并发请求，不持久缓存整个视野；不是全城预热。若已截断，数量只代表已加载部分。

商家自助或平台新增、修改、归档，以及停用账号，均在仓储写入成功后失效缓存。更新同时清理原/新位置网格，并推进全局商家 generation：这是偏保守的失效，会使其他商家网格也重新加载，确保跨格移动与账号停用不残留。写入失败不清缓存；旧 generation 的后台查询不能回填缓存。Redis 无法访问时，商家读库；失效失败的当前实例持续绕过缓存并在恢复后重新推进 generation。若失效失败时其他实例仍能读取旧缓存，最多等原 45 秒 TTL；当前没有事务 outbox，不能声称跨数据库/Redis 强一致。

### 热点与独立预算

复用现有 Redis，专用前缀 `cityflow:{map-cache}:v2:`，缓存键中的查询经过 SHA256，原始搜索词/用户 ID 不写入键。热点记录保留每个查询最近 21 个访问时间，以滚动 10 分钟超过 20 次准入，最多跟踪 4096 个查询。桂林名称/450300 的边界和明确指定桂林的地点搜索可强制准入；不批量预取该城市的其他结果。

`MAP_CACHE_MB=128` 限制地图结果与热点元数据结构的 Redis MEMORY USAGE 总量，Lua 按 LRU 淘汰旧结果，必要时淘汰热点计数。单响应最多缓存 1 MiB，最多 4096 个结果。每个结果采用 Redis 原生 TTL，到期即不可读取，不依赖下一次访问来删除内容；目录只保留计费大小及哈希，惰性清理不会延长结果保留期。此预算不等于 Redis 整个进程 RSS，少量配额/generation 键、Redis 分配器及执行期间临时内存不在预算内。不会修改 Redis 全局 maxmemory，也不会淘汰骑手 GEO、认证缓存或骑手轨迹。老商家 generation 数据随 TTL/预算淘汰。

### 市中心搜索 Redis 缓存

市中心地点搜索复用现有 Redis `MapCache`，不再维护 MySQL `map_query_cache`。搜索请求先读 Redis；未命中才走高德，成功后写回 Redis，下一次其他账号查同一城市与关键词可直接复用：

| 接口 | 缓存条件 | 逻辑键 |
|---|---|---|
| 地点搜索 `/map/search` | `city` 为默认城市、去“市”别名或 `450300`，命中 `HotCities` 强制写缓存 | `amap:search:v1:<城市>:<小写关键词>` |

搜索 TTL 固定 1 分钟；键和值都不含账号、用户 ID 或精确浏览器坐标。Redis 是唯一缓存，不写 MySQL，也没有跨库一致性设计；Redis 到期即失效，Redis 故障时直接回源高德。命中时不会调用高德；未命中仍经过 `MapCache.Allow` 的进程内配额和单进程 singleflight。附近地点沿用既有 Redis 热缓存；逆地理地址不再额外持久化。路线、城市和行政区边界继续使用原有 Redis 缓存。

市中心城市名和 `450300` 同时被视为热点：第一次行政区校验会把边界强制写入 Redis（1 小时），供后续搜索过滤复用。`TrustedSearch` 在结果中的每个地点都已存在于 `trusted_places` 且未过期时，直接返回已存版本，不再调用边界接口；因此缓存命中在边界服务慢或高德配额用尽时仍可完成。首次出现的新地点、部分未验证结果或可信地点已过期时，才重新做行政区校验并写入可信地点。

### 高德缓存许可和故障行为

依据 [高德服务条款](https://lbs.amap.com/home/terms)，能否保存接口结果及保存多久需按具体授权确定，不能因为有 Key 就永久保存。默认 `MAP_AMAP_CACHE_ALLOWED=false`：不在 Redis 保存高德结果，仍有请求合并、总配额和超时；页面内复用已展示边界和未变更起终点的路线。获得许可后明确设为 true，再按授权调整各 TTL。默认边界 3600 秒，另允许 TTL/4 的过期继续服务窗口；配置时必须把这段窗口也算入获准保留时间。边界 TTL 最长 7 天、搜索最多 1 分钟、城市最多 1 小时、路线最多 5 分钟，代码上限不代表供应商授予相应许可。搜索/城市/路线默认 TTL 分别为 60/600/60 秒，且仅热点查询准入。

相同查询通过进程内 singleflight 合并；100 个同时等待同一查询时共用一次加载。首个客户端取消不取消其他等待者，单次加载最长 12 秒，供应商 HTTP 最长 10 秒，每进程最多 32 个不同查询同时加载。启用获准缓存时，过期边界先返回旧内容并启动一次后台刷新，刷新失败保留仍在允许窗口内的旧值。

`MAP_PROVIDER_REQUESTS_PER_MINUTE=60` 通过 Redis 分钟计数限制所有实际高德调用；命中缓存不耗额度。Redis 故障时每进程按固定窗口限流，避免故障后完全失去保护。配额是固定分钟窗口，可能在分钟边界出现两倍瞬时突发；Redis 故障时多实例配额会叠加。请求合并目前限单进程，多实例同时冷查可能各调用一次；多实例严格合并需额外的跨实例协调，不能将本实现宣传为分布式 singleflight。

地点搜索只在提交时请求；地图视野变化只加载平台点位，不请求 POI。骑行路线只在点击规划时调用，起终点和所选任务未改变则复用，10 秒骑手刷新不触发重规划。高德底图瓦片由 SDK 管理，没有下载、入库或全城离线缓存。骑手 Redis GEO 与 Redis 待归档轨迹不参与热点淘汰。

### 本轮验证

Go 全量测试及 Redis 实测覆盖：100 并发同查、等待者取消、失败不缓存、热点门槛、预算淘汰、SWR、失效 generation、商家旧/新范围更新以及认证限流；浏览器脚本 `scripts/map-city-smoke.cjs` 验证真实高德桂林识别、全市范围、边界多边形、定位、视野防抖，并用接口夹具验证聚合展开。`map-amap-smoke.cjs` 与 `merchant-map-smoke.cjs` 验证现有骑行、实时跟踪和商家自主管理。浏览器测试使用独立内存演示服务与本机 Redis，不等同本轮真实 MySQL 验证。


## 模拟骑手演示（2026-11-09）

项目演示优先使用模拟骑手，无需真人持续移动或授予 GPS 定位权限。用户先创建含取件、送达坐标的任务，骑手接单后在地图“跟踪任务”选择这单，点击“开始模拟骑行”。模块只在骑手页面加载；默认速度 18 km/h，可在启动前选择 10、18、25 或 36 km/h。

启动时请求一次现有高德骑行接口，取得道路折线并转成 WGS84。模拟器按球面距离累计各段长度，以实际经过时间乘速度求出已行驶距离，再在相应路段内插值，避免按数组下标前进导致长短路段速度不同。约每 4 秒上报一次，方向及标记平滑移动继续由现有地图适配器处理；没有在每个位置更新时重新调用路线规划。

### 模块边界

| 文件 | 职责 | 不承担的职责 |
|---|---|---|
| `web/assets/rider/route-simulator.js` | 独立路线采样与定时推进，注入 publish、时钟和调度器 | 不依赖高德、Leaflet、DOM、账号、任务或 HTTP，可直接用 Node 测试 |
| `web/assets/shared/location-feed.js` | 位置来源租约、串行上报、最小 3.2 秒发送间隔、取消旧来源 | 不依赖地图或业务 URL，由调用方注入发送及回调 |
| `web/assets/rider/simulation.js` | 骑手模拟面板、读取选中任务、调用现有路线 API、启停和任务状态检查 | 不实现道路算法或另建任务/轨迹业务接口 |
| `web/assets/shared/map.js` | 注入现有位置 API 与地图标记回调，向骑手模拟模块提供位置通道及路线绘制接口 | 不包含匀速采样、模拟定时器或模拟面板 |

真实 GPS 和模拟位置通过同一位置通道，每次只允许一个来源写入。启动模拟会停止真实共享并禁用该按钮，停止模拟后可手动开启真实定位，不会自动恢复 GPS。通道串行等待旧发送结束并保持最小间隔，切换来源时旧回调不能覆盖新来源标记。

每次模拟上报前读取任务确认仍属于当前骑手且处于 CLAIMED / ARRIVED / PROCESSING，取送坐标改变、权限丢失、任务结束或请求失败时停止；切换任务、点击停止、离开页面也会取消后续动作。到终点只停止模拟，不自动推进任务状态；再次开始会从路线起点重新演示，不是暂停续骑。

模拟调用现有 `POST /api/v1/riders/me/location`，仍受服务端身份、角色、坐标、频率和来源校验。用户通过原 REST / WebSocket 查看移动；定位观测按骑手追加到 Redis 待归档 ZSET，不再按任务复制，任务历史按 `task_events` 时间窗合并查询 MySQL 归档和 Redis 待归档点。内存模式重启清空；Redis 待归档点在归档成功后删除，MySQL 归档当前永久保留。无需模拟专用数据库表、服务端线程或放宽业务权限。同一个骑手同时履约多个任务时，共享同一份骑手轨迹，不会重复写点；演示时仍建议单任务以便阅读。

面板明确标注为模拟骑手；模拟观测进入同一轨迹归档，`source=simulated` 用于和真实设备区分，但客户端自报来源不能证明位置真实性，不能据此声称这些点是真人实测。停止后已接受的位置与轨迹仍保留，当前位置按原两分钟期限过期。模拟依赖骑手页面保持运行，关闭页面即停止，浏览器后台节流会影响采样频率；不是服务端离线常驻模拟器。高德路线暂不可用时显示错误，不伪造沿真实道路行驶。

### 验证

`node --test scripts/route-simulator.test.cjs` 覆盖路段长度差异、转弯、端点、按实际时间匀速采样、停止、错误处理和位置源替换。`scripts/rider-simulation-smoke.cjs` 通过 `CITYFLOW_TEST_URL` 指向可丢弃演示服务，创建任务并模拟上报，验证真实高德骑行路线、近似速度、用户实时标记、历史观测、手动停止、真实 GPS 与模拟切换、终点停止、任务状态不被自动改变、取消后停止及手机布局。终点测试使用短路线接口夹具，其他主流程使用真实高德路线；不得向正式业务库运行此脚本。


## 桂林任务服务范围（2026-11-13）

用户发布及修改取送地点时，任务服务要求每个取件点及送达点有有效 WGS84 坐标，使用与前端相同的坐标转换将其转换为 GCJ02，再检查是否位于 `450300` 桂林市行政边界。边界来源当前为高德行政区接口；本地 `guilin_boundary` / `guilin_admin` 代码保留但未接入运行路径。边界服务不可用返回 503，不把校验失败当作市内；高德 Web 服务 Key 缺失时无法新建任务。既有任务若不修改地点，仍可修改标题等内容；修改地点必须重新选点和校验。已成功创建任务的幂等重试先返回原任务，即使边界服务暂时不可用也不会重复创建。边界接口的缓存仍遵循 `MAP_AMAP_CACHE_ALLOWED` 与配置 TTL，范围校验不写入精确用户位置缓存。坐标转换参考本项目已包含 MIT 许可的 `wandergis/coordtransform`。

当前城市限制是桂林，骑手服务区域、最大距离、最大并行数目前只是资料，开放任务未按距离筛选，也未用这些字段拒绝接单；是否启用相应业务规则待产品确定。实时连接与最近位置时间分别显示；设备和模拟上报在实时及历史数据中带来源，历史记录中的 unknown 表示旧记录未记录来源；客户端自报来源不能证明位置真实性。


## 可信地点与任务接口（2026-11-13）

搜索或地图点选附近地点时，后端调用高德并以 GCJ02 行政区多边形筛选真实 POI；当前没有可用的 `local` 查询路径，`MAP_SERVICE_PROVIDER=local` 仅被解析，不参与 provider 选择。通过的 POI 按 ID 写入 MySQL `trusted_places`（内存模式仅存在本进程），浏览器只提交选中的 POI ID。地图空白处用附近查询返回 POI，不能直接把逆地理地址作为任务地点。前端输入的地址和坐标不作为任务保存依据。

创建和修改任务都批量查询全部取件点及送达 POI ID，未命中或已过期直接拒绝，不访问高德；服务端用可信地点名称、地址和 GCJ02 转换后的 WGS84 坐标写入任务快照。POI ID 不是秘密，也不需要用户绑定或 Redis 随机凭证。旧任务缺少 POI ID 时编辑需重新搜索选择；历史记录仍可查看。

`TRUSTED_PLACE_TTL_SECONDS` 默认 1800 秒，最多 7 天，允许值应按高德对应授权调整；有效期内已存在的 ID 保留数据库中的地址、坐标和原到期时间，不重复覆盖或延长有效期；搜索界面展示该数据库版本，与任务保存一致。过期记录不能用于发布，下次搜索会针对这些 ID 清理并重新写入；其他过期记录由 Discovery 的 `discovery.trusted-places.purge` 定时任务分批物理删除，不再依赖用户再次搜索。任务快照独立保存。受限高德调用仍有 Redis 共享配额及账号、传输对端 IP 每进程限流；反向代理部署需在入口按真实客户端 IP 限流。


## 联网查询缓存与离线地图的边界（2026-11-13）

附近地点查询使用现有统一地图服务：Redis 中相同坐标的结果未过期时复用，未命中或 Redis 不可用时调用高德；随后仍按桂林边界过滤并登记可信地点。附近查询默认缓存 5 分钟，随搜索缓存 TTL 配置，只有明确启用高德结果缓存才保存，缓存键哈希后存储。关键词、城市、边界和路线按各自既有准入及 TTL 策略处理；逆地址查询仍直接请求高德。

缓存不能构成完整离线地图或离线地点库。项目目前没有可用于 Web 的离线地图包、离线 POI 地址索引，也未支持离线路线规划。平台商家由 MySQL 管理并可缓存到 Redis，其可用性仍取决于 CityFlow 服务是否可访问。
